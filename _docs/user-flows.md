# Пользовательские сценарии

## Кандидат: путь до категории

```
Регистрация (e-mail + пароль)
   ↓
Подтверждение e-mail (прототип: любой 6-значный код)
   ↓
Заполнение профиля (ФИО, контакты, стек)
   ↓
Опрос: отрасль → специализация → предполагаемый грейд
   ↓
Тест: 5 заданий, сгенерированных LLM под профиль
   ↓
Оценка, присвоение категории (например, «Backend · Middle»)
   ↓
Профиль: текущая категория + история попыток + кнопки
«↑ Выше» / «↓ Ниже» с блокировкой на 90 дней
```

## Кандидат: история и смена грейда

```
Профиль → блок «Категория и грейд»
   ↓
Видно текущую категорию («Backend · Middle») + таблицу попыток
   ↓
Кнопки «↑ Выше» / «↓ Ниже» (активны, если прошло 90 дней с последней
попытки на этот грейд)
   ↓
Клик → /survey.html?spec=backend&grade=senior
   ↓
Специализация и грейд предзаполнены, отрасль выбирается вручную
   ↓
Старт теста → результат → возврат в профиль
```

## Кандидат: получение приглашения

```
Работодатель нашёл категорию «Backend · Middle»
   ↓
Просмотрел профили, выбрал кандидата
   ↓
Отправил приглашение с вилкой зарплаты
   ↓
Кандидат видит приглашение в /offers.html
   ↓
Открывает приглашение → статус viewed
   ↓
Принимает или отклоняет
   ↓
При accepted: работодатель видит контакты
```

## Кандидат: настройки приватности и ФСП ID

```
Профиль → Настройки (/settings.html)
   ↓
Приватность: тумблеры «Стек», «Опыт», «Софт-скиллы»
   ↓
Сохранить → PATCH /profile/me { visibility }
   ↓
ФСП ID:
   • если не привязан — поле ввода + кнопка «Привязать»
   • если привязан — бейдж + значение + кнопка «Отвязать»
   ↓
Согласия (152-ФЗ):
   • «Обработка ПД» — с регистрации, отозвать нельзя
   • «Публикация профиля» — кнопка «Дать согласие»
     → POST /profile/consents
```

## Работодатель: работа с подборкой и приглашением

```
Регистрация → профиль компании
   ↓
Описание потребности: специализация, грейд, стек, «о команде»
   ↓
Подборка: кандидаты по категориям
   • сверху — с лучшим тестом и ФСП
   • в строке «почему в подборке» — объяснение
   ↓
Карточка кандидата: стек, опыт, софт-скиллы, ФСП
   • контактов нет — только анонимный ID
   ↓
«Пригласить» → форма с описанием и вилкой ЗП
   ↓
Мои приглашения: sent → viewed → accepted/rejected
   • email кандидата виден только при accepted
```

## Дополнительный сценарий: кандидат без истории ФСП

Показываем отдельно, потому что это обязательное требование ТЗ:

1. Кандидат регистрируется, привязки к ФСП нет.
2. В `settings.html` — блок «ФСП ID не привязан» с нейтральным текстом
   и полем ввода.
3. Работодатель видит профиль, блок достижений ФСП — пустой с пояснением
   «ФСП не привязан».
4. Категория и приглашения работают как обычно.

```
[0:35] Категория присвоена: «Backend · Middle», score 78%
[0:40] Настройки: включаем приватность «Софт-скиллы», привязываем ФСП ID
[0:45] Профиль: видна история попыток + блокировка «↑ Выше» до DD.MM
[0:50] Переключаемся на работодателя
[0:55] Описывает потребность: Backend, Middle, Go
[1:00] Подборка: топ-5 с объяснением
[1:05] Открывает карточку → контактов нет
[1:10] Отправляет приглашение с вилкой 250–350к
[1:15] Кандидат видит приглашение, принимает → контакты раскрыты
[1:20] Готово
```

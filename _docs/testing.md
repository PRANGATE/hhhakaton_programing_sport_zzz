# Тестирование

## Пирамида

```
        ┌──────────────┐
        │     E2E      │  Playwright, 10–15 сценариев
        ├──────────────┤
        │ Integration  │  API + PostgreSQL, 30–40 тестов
        ├──────────────┤
        │    Unit      │  Сервисы, валидация, 100+ тестов
        └──────────────┘
```

## Unit

- Node.js `node:test` + `assert`.
- Что тестируем: бизнес-логика сервисов, валидация (`zod`-схемы),
  утилиты.
- Покрытие целевое — ≥ 60% по критичным модулям.

## Integration

- Каждый API-эндпоинт: happy path + 2–3 негативных.
- Тестовая БД — отдельный docker-compose с PostgreSQL.
- Миграции прогоняются перед тестами.

## E2E

Playwright. Обязательные сценарии:

1. Регистрация кандидата → опрос → тест → категория.
2. Работодатель описывает потребность → подборка → приглашение.
3. Кандидат принимает приглашение → контакты раскрыты.
4. Отсутствие истории ФСП — профиль работает.
5. Rate-limit на `/auth/login`.

## Contract-тесты

- OpenAPI-спецификация — источник правды.
- CI проверяет: реализация соответствует спеке.
- При выносе сервисов — Pact (или аналог).

## Нагрузочное

k6. Сценарии:

- 1000 одновременных пользователей, `list-candidates` 10 минут.
- Целевые SLO: p95 ≤ 300 ms, error rate < 0.5%.
- LLM-эндпоинты — отдельно, p95 ≤ 10 s.

## Ручное тестирование

- Чек-лист перед сдачей: сквозной сценарий из ТЗ, 3.3.
- Проверка в Firefox и Chrome.
- Проверка на мобильном разрешении (хотя адаптивность опциональна).

## CI (Post-MVP)

GitHub Actions:

1. `lint` (eslint)
2. `unit`
3. `integration` (с PostgreSQL-сервисом)
4. `e2e` (Playwright)
5. `build` (docker)
6. `contract` (openapi validator)
